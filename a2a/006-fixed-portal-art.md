# 核心 Portal 固定区域与入口标签修订方案

## 1. 中央 6×6 固定空间布局
以世界坐标原点 `(0,0)` 为核心建立 6×6 的独立网格。该区域的地形、路径与资产位置强制固定，不受每日随机 Seed 干扰，作为站点的常驻 Portal。
*   **(0, 0)**: 玩家出生点。角色 `Rogue` 初始站立于此。
*   **(0, 2)**: 放置 `hub (tavern)`，作为“日志/关于”功能入口。
*   **(-2, -1)**: 放置 `home`，作为“项目/作品集”功能入口。
*   **(2, -1)**: 放置 `mill`，作为“工具/实验室”功能入口。
*   **周围点缀**: 在 6×6 网格的剩余关键节点与边界处，固定布置 `tree`、`pine` 与 `rock`，配合固定道路，实现与外部随机生成网格的自然接缝。

## 2. 镜头与核心交互逻辑
*   **初始视场**: 进站首屏镜头近距离聚焦于中央 6×6 区域。玩家需通过拖拽画布或缩放视野（Zoom Out），才能发现外围每日随机生成的扩展世界。
*   **状态保持**: 界面底部中央固定显示 d6 移动掷骰 UI。
*   **快速归位**: 任意时刻点击主角 `Rogue`，触发“返回出生点”逻辑，镜头平滑追踪回 `(0,0)` 并恢复初始缩放层级。

## 3. 世界坐标入口标签表现（三种原型变体）
彻底废弃居中卡片与边缘导航栏。所有入口标签严格锚定于对应建筑的三维坐标（如 `y+2.5` 顶部位置）。统一适用缩放规则：当镜头与聚焦点距离（Distance/Zoom）大于设定阈值时，标签渐隐收缩，保证鸟瞰模式下地图纯净。

针对世界内标签的渲染呈现，设定以下三种变体供视觉比对：
*   **变体 A：CSS 2D 投影层 (World-to-Screen Overlay)**
    *   **实现**: 读取建筑 3D 坐标实时转换为 Canvas 上层绝对定位的 HTML DOM 节点。
    *   **表现**: 文字边缘绝对锐利，UI 属性最强；拉远时通过 CSS 监听距离改变 `opacity` 渐隐。
*   **变体 B：3D 广告牌 (Sprite/Billboard)**
    *   **实现**: 将文字渲染为 CanvasTexture 并生成 3D 平面材质，设置始终 LookAt 相机。
    *   **表现**: 材质受世界空间景深与光照影响，随镜头拉远有自然透视缩小过程，达到阈值后销毁 mesh 渲染。
*   **变体 C：极简标记 + 临近展开 (Proximity Expand)**
    *   **实现**: 建筑上方默认仅悬浮发光的微小几何提示（如纯色菱形），只有当玩家掷骰控制 `Rogue` 走到该建筑相邻格，或鼠标精准 Hover 时，才在其上方展开完整文字标签。
    *   **表现**: 对 3D 场景视觉入侵最小，沉浸感最强，鼓励玩家实际移动探索核心区。
